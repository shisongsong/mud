# ADR-0004：不可变配置版本与Release激活指针

- 状态：Accepted（用户委托下采用设计；独立评审/运行验证未执行）
- 日期：2026-09-30
- 影响：T07–T08、T14–T15、T20及所有规则/内容读取方

## 背景

后台发布配置时，已创建试炼、排队任务或Saga可能仍在运行。覆盖同一配置行会令重试结果依赖当前时间，从而造成玩法漂移和不可审计。

## 决策

配置保存不可变版本，ReleaseManifest引用精确版本；Control事务写激活指针/审计/Outbox。gameplay与glossary独立指针；试炼/Saga固定创建时玩法版本，术语即时更新、历史文本冻结。worker/server校验后原子切换，新根命令必须具备数据库指针所指精确快照，否则503，不用旧快照接纳。历史激活重新指向旧清单，不覆盖历史。

## 考虑过的方案

- 原地覆盖配置：无法还原在途行为，不采用。
- 每次执行读最新配置：重试不确定，不采用。
- 不可变版本+显式激活：便于复现和审计，作为提案。

## 后果

- 需要版本保留、兼容检查、清理策略和配置checksum。
- 旧版本需至少保留到所有引用它的房间、Saga、任务退出生命周期。
- 激活失败必须保留旧快照；提示丢失需通过轮询版本收敛。
- 操作系统时钟不能替代持久化版本/生效策略。

## 验证与批准

用户2026-09-30委托助手采用此设计；已发布版本首发保留，引用安全清理以后另评估。T07/T20验证并发草稿、校验失败、激活故障、提示丢失及旧Saga恢复，当前未执行，不以Accepted替代证据。
