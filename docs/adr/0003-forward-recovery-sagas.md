# ADR-0003：跨聚合流程默认前向恢复

- 状态：Accepted（用户委托下采用设计；独立评审/运行验证未执行）
- 日期：2026-09-30
- 影响：T06、T12、T14–T15及后续交易/契约

## 背景

试炼结算和信息传播会影响多个独立聚合。单一关系数据库事务无法覆盖所有目标，又不能通过恢复旧快照安全撤销已经发生的其他合法更新。

## 决策

每个跨聚合流程以持久Saga/operation记录定义版本、步骤、目标、命令ID、效果唯一键、结果、重试时间和状态。业务步骤逐目标提交；暂时错误重试，永久错误暂停并告警/人工处理。默认前向恢复直到完成。若业务确需撤销，以关联原效果的逆向账本/授予凭证处理，不执行覆盖式回滚。

## 考虑过的方案

- 跨聚合单事务：不可行且破坏模块所有权。
- 恢复所有聚合旧值：可能覆盖后续合法写，不采用。
- Saga前向恢复+精确补偿：保留历史并可追踪，作为提案。

## 后果

- 用户界面必须显示pending/部分失败并允许查询操作状态。
- Saga步骤需稳定幂等键，命令结果可审计。
- 永久错误由ops经审计重试固定payload，不能跳过目标。Query参与槽保留到正常终结，避免“错误放行”；SLO/恢复目标见M0决策，均待实测。
- 裁决结果和随机种子固定，重试不能重新裁决或改变奖励。

## 验证与批准

用户2026-09-30委托助手采用此设计。T06/T15须在每步骤提交点注入重启/重复，检查积分账本、逐卡Script创建/知识授予、Board和Query结果；当前未执行。任何恢复不允许跳过业务目标后把Saga标Done。
