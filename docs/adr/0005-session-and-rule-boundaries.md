# ADR-0005：会话身份与受限规则执行

- 状态：Accepted（用户委托下采用设计；独立评审/运行验证未执行）
- 日期：2026-09-30
- 影响：T02、T09、T17–T20、管理与玩家接入

## 背景

客户端输入和可配置玩法规则都不可信。若客户端能声明actor/角色权限，或规则能执行任意代码、读取ORM对象、直接写其他模块，便会绕过授权及资源不变量。

## 决策

默认采用同源HttpOnly Cookie会话、CSRF和Origin验证，口令采用Argon2id；server从已验证会话建立Actor，body不接受可信身份字段。WebSocket握手校验会话/Origin，每条消息继续校验权限和成员关系。DSL仅是经schema校验的AST，由纯解释器执行；字段/函数/效果白名单、预算和持久化去重均由服务端强制，规则效果通过目标模块公开命令重验不变量。预览只注入纯计算/测试端口，不持有真实副作用适配器。

## 考虑过的方案

- localStorage长效bearer token：增加脚本窃取面，不采用。
- eval/Function/动态模块：不可控执行能力，不采用。
- 管理员与玩家共用相同规则能力：权限范围过大，不采用。
- Cookie会话+能力受限AST：减少客户端信任和执行面，作为提案。

## 后果与实施要求

- 会话期限、Cookie属性、管理TOTP/恢复码/再认证、限流参数按 [M0决策](../m0-decisions.md)第6节执行，生产默认fail-closed；不允许用admin隐式绕过职责能力。
- DSL解释器需确定性、可预算、可拒绝超限；禁止把事实快照扩大为全部玩家秘密。
- 首个管理员受控bootstrap无默认密码，rule_admin批准规则checksum、lead_planner/admin激活且不能绕过审批；ops只持久暂停/恢复固定计划，不能改奖励。设计已决定，生产安全验证仍需独立证据。
- 安全测试必须验证跨账户IDOR、Origin/CSRF、消息大小、越权效果、预览零副作用和秘密序列化。

## 验证与批准

用户2026-09-30委托助手采用此设计。T09/T17/T18/T20须提供真实接入/解释器/端到端安全测试；[威胁模型](../threat-model.md)定义控制与验证责任，当前未实测。拦截即停，不调整安全产品或绕过控制，Accepted不代表安全审查通过。
