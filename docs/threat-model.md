# MVP 威胁模型与验证责任 v1.0

> 设计已采用，未运行安全测试；不是渗透测试报告或法律合规意见。依据 [M0决策](m0-decisions.md) 和 [基线](../baseline.md)。用户授权助手作出设计取舍，实际对公网发布必须通过T26/T27。

## 1. 资产和信任边界

- 资产：认证凭证/会话/MFA、玩家知识秘密、积分与Board账本、投票/裁决/随机种子、配置权限与历史、消息/审计、备份和操作恢复能力。
- 不可信输入：浏览器HTTP/WS、玩家文本、管理员草稿（管理员也可能误操作）、集成事件/存量数据、重放/重建输入。
- 边界：浏览器→同源接入→会话授权→模块命令；模块→自己的表；跨模块→公开端口/持久事件；server/worker→数据库/Redis；Control→不可变清单；运维→授权恢复/备份。
- 平台数据库连接持有必要事务能力，但不得因此允许模块跨所有权读写。静态依赖检查和仓库适配器审查共同保证边界，不能声称一个共享DB账号提供完整租户隔离。
- 攻击者：未登录请求、合法玩家越权、被盗管理会话、恶意/错误发布、重复请求/重放、故障worker。不得假设“管理员输入天然可信”。

## 3. 额外接入防护

- HTTP正文默认32KiB，受控配置上传最大256KiB；显式路由上限，JSON嵌套深度上限与schema大小约束，超限413，不先全量缓冲无限正文。
- CSP生产默认script-src 'self'、object-src 'none'、base-uri 'none'、frame-ancestors 'none'；不引入unsafe-eval。字体静态资源本地打包，不强迫运行时外网请求。
- 反向代理可信来源显式配置，不任意相信X-Forwarded-For。错误、trace导出和readiness不暴露数据库/secret；liveness/readiness限制响应信息。
- 管理账号与玩家身份是独立能力；无任意管理SQL/资源delta/重设积分入口。只恢复固定计划，重新派发必须有理由/权限/审计。
- 举报不能让举报人读取目标秘密。审查员只读取必要范围证据；禁言由Social权威策略执行，禁用由Identity公开命令执行，跨域协调持久化且保守拒绝新发送。

## 4. 接受的残余风险与上线门禁

- 在线判定基于30秒近似心跳，不代表真实人类在线；明确对外呈现，不用它证明付款/获得知识。
- 同数据库部署存在共享故障域；选择可恢复流程而非宣传强一致/零丢失。
- MVP没有玩家屏蔽、私聊或自助重置密码；不能宣传已具备这些能力。账号删除/导出走受控运营流程。
- 管理规则审批MVP允许同账号不同能力，不提供强双人隔离；对公网生产可用配置要求分权，作为运营风险记录。
- 反作弊不能仅靠隐藏种子；对外解释个人计分，任务限定首发奖励不构成现金经济。职业无额外权限，不承诺未实现平衡玩法。
- 精确版本、Argon2性能、压测、恢复目标、安全反例、地区隐私和未成年人政策均需上线前验证；当前无通过证据。发现阻断风险即停止上线，不停止无关隔离设计/编码。
