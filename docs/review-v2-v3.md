# 架构风险与基线重构说明

## 结论

本说明列出新基线针对的设计风险，不是原文逐项差异报告。不能认定下面风险全部存在于旧文档。用户已授权以当前设计为新起点，不再把无法核实旧文当开发阻塞。

多人文字与配置规则项目若未定义一致性和安全协议，交给多个Agent容易各自猜测，导致重复奖励、无限规则触发、秘密泄露或不真实的完成声明。

保留多人文字、信息博弈、配置驱动和涌现，改为模块化单体、可恢复异步流程和受限规则，分出MVP/R1/R2。

## 问题与处理

| 级别 | 待防范或核实的风险 | 新基线的处理 |
|---|---|---|
| 阻断 | 单聚合事务与批量知识库传播冲突 | 持久化传播，逐收件人幂等事务 |
| 阻断 | Inbox插入与业务没有原子性说明 | 同事务，失败一起回滚 |
| 阻断 | EventBus/Redis无可靠订阅者交付协议 | 持久delivery、租约/重试/DLQ；Redis仅提示 |
| 阻断 | 回滚积分/知识覆盖后续合法变更 | 前向恢复、关联逆向账本、精确授予凭证 |
| 阻断 | 玩家可使用管理员同等规则效果 | 白名单模板、能力矩阵、审核+逐版本同意 |
| 阻断 | 规则无限递归且没有跨worker限制 | 深度/事件/效果/计算预算、共享计数、停用 |
| 阻断 | DSL及上下文权限未定义 | AST解释器、字段白名单、快照/目标重检 |
| 高 | 阅读信息似乎自动接受规则 | 独立明示同意，不因阅读生效 |
| 高 | 规则条件不保证执行时资源仍够 | 目标不变量验证、资源预留、积分与货币分离 |
| 高 | Rules与配置面重复拥有规则定义 | Control拥有定义，Rules拥有执行/授权 |
| 高 | 热更新混用在途版本 | release原子激活、房间/Saga固定版本 |
| 高 | rules只有一行版本，无可靠发布历史 | 不可变版本、激活指针、审计 |
| 高 | 预览只要求无数据库写，仍可能推通知 | 无真实写/通知/任务端口的纯沙箱 |
| 高 | ORM/WS/日志泄露隐藏真伪 | 独立公开DTO、白名单与秘密测试 |
| 高 | 断线/计时/恢复缺失 | deadline、持久任务、序列/快照恢复 |
| 高 | WS无逐消息认证和成员验证 | 会话/Origin/CSRF/授权/背压 |
| 高 | NULL scope_id绕过术语唯一键 | 非空规范值或NULLS NOT DISTINCT |
| 高 | 管道任意关闭授权等核心步骤 | 不可编辑强制步骤，R2才可视化 |
| 中 | 重复SQL、缺少version/约束/去重 | 单份schema/迁移契约，专职维护 |
| 中 | ORM要求与SQL迁移互相模糊 | 允许静态迁移/参数化接口，禁用户SQL拼接 |
| 中 | 所有事件持久化易误解为事件溯源 | 集成事件归档，明确非Event Sourcing |
| 中 | tension与“稳定度”数值方向冲突 | 固定压力语义，稳定度单独派生 |
| 中 | 阵营力量的百分比定义不明 | 独立0–100强度，占比另定义 |
| 中 | 职业标识绑定显示世界观 | 使用中性编号，M0确认编号数量 |
| 中 | 术语调用参数与接口不一致 | 分开name/description/metadata hooks |
| 中 | 识别策略无统计/证据/误报标准 | R2确定性统计、证据、候选审核、合成集 |
| 中 | <1s未定义负载/百分位 | 明确负载、环境、p95/p99和故障例外 |
| 中 | 固定总工期低估风险/质量成本 | 按任务范围与门禁估算 |
| 中 | 自动提交/执行忽略安全拦截 | 明确许可，拦截即停，未运行不冒充验证 |

## 取舍

- 首版不拆微服务、不实现通用加载器/无限规则/拖拽Saga，减少基础框架成本。
- 先证明信息传播与四人裁决可玩性，再开发玩家契约、反馈、元规则。
- 不追求全局事务或端到端exactly-once，依靠幂等、账本和故障恢复保证业务正确性。
- 不删除涌现目标，变成有安全边界和可验证质量的后续版本。

上述玩法、传播、奖励、版本、管理员和保留期已在 [M0决策定稿](m0-decisions.md)具体确定，基线升为v3.1。MVP写入口统一HTTP，WS仅提示和快照刷新；角色能力暂不差异化，首发内容保证证据可推理，而非随机万能剧情。
